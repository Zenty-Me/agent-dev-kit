## python项目

```
请自主遍历并阅读当前工作区内的整个 Python 项目，在不改变任何原有业务逻辑的前提下，为全项目所有核心 Python 源码文件就地（in-place）补充规范的文档注释和深度行内解释。

---

### 一、执行流程与范围

1. **项目扫描与定位**：
   - 扫描当前仓库，识别入口文件（如 `main.py`、`app.py`、`cli.py`）及核心模块。
   - 仅处理本项目的业务源码文件（如 agent 核心、工具集、提示词模块、终端交互层等）。
   - **忽略非业务目录**：跳过 `.venv`、`venv`、`__pycache__`、`.git`、`dist`、`build` 及第三方依赖目录。

2. **自底向上逐文件修改**：
   - 先理解项目整体调用链路，然后由底层依赖模块（如 utils、tools、schemas）向顶层核心（如 agent_loop、cli 入口）逐个文件进行就地修改写入。
   - 每完成一个文件的注释，确保该文件语法正确且无逻辑变动后再处理下一个文件。

---

### 二、注释与文档规范

1. **模块与类/函数 Docstring（Google 风格）**：
   - **文件顶部**：每个 `.py` 文件顶部补充模块级 Docstring，阐明该模块在 Agent 系统中的核心职责与依赖关系。
   - **类与函数**：必须补充完整 Docstring，明确包含：
     - **功能说明**：简明概括其作用。
     - **Args**：参数名、类型及业务含义。
     - **Returns**：返回值类型及结构含义。
     - **Raises**：显式抛出或捕获的关键异常。

2. **Agent 核心机制重点行内注释（必须解释“为什么这样设计”与“底层机制”）**：
   - **思考与执行循环**：解释 ReAct 循环的推进逻辑、最大轮次保护、终止条件判断。
   - **Prompt 与模板**：解释系统提示词组装、变量注入与 Few-shot 上下文构造。
   - **输出解析（Parser）**：解释针对 LLM 输出的正则提取、Markdown 代码块剥离、JSON 容错解析等逻辑。
   - **工具注册与反射调用**：解释工具元数据定义、参数反序列化校验及动态分发执行流程。
   - **上下文/记忆管理**：解释对话历史追加、Token 计数截断或滑动窗口机制。
   - **终端交互/流式处理**：解释 CLI 输入输出捕获、流式渲染或 Rich 终端美化逻辑。

3. **代码隐患与特殊标记**：
   - `# NOTE:` 标注非直观的代码技巧、Hack 写法或特殊折中实现。
   - `# WARNING:` 标注可能引发 LLM 死循环、Token 溢出、JSON 解析崩溃、未捕获网络异常的边界隐患。
   - `# BUG:` 标注代码中已存在的潜在逻辑缺陷或未处理异常。

4. **类型注解补充**：
   - 在不破坏现有运行机制的前提下，为缺失注解的函数补齐 Python 3.10+ 标准 Type Hints。

---

### 三、硬性约束

1. **逻辑绝对零改动**：
   - 严禁修改任何现有的代码执行逻辑、控制流、函数签名、类名、方法名及变量名。
   - 严禁直接进行所谓的“代码重构”或“性能优化”（若有重构建议，仅以 `# NOTE:` 形式写在注释中）。
2. **完整写入**：
   - 保持文件原有所有代码完整，禁止使用省略注释（如 `... remaining code ...`）缩减代码。
3. **语言要求**：
   - 所有新增的 Docstring、行内注释、标记说明均使用**简体中文**。
4. **可运行性**：
   - 所有修改必须保持 Python 语法合法，不可引入语法错误或循环导入。
```
